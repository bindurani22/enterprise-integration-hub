# Design Decisions

The following architectural decisions were made to address bank's integration complexity, scalability, reliability and governance requirements.

### 1. Centralized API Gateway

Use a centralized API Gateway as an entry point for all API-based integrations.

#### Reasons:
- Provides a consistent security boundary
- Centralizes API policies such as throttling and authentication
- Avoids exposing backend services directly
- Simplifies API lifecycle management

### 2. Separate Workflow Orchestration from Integration

Workflow Engine is kept outside the Integration Hub.

#### Reasons:
- Workflow engine owns business process orchestration
- Integration Hub owns technical system integration 
- Prevents Integration services from becoming business process engines
- Allows both services to evolve independently

### 3. API-based communication for Synchronous Interactions
Use API calls for interactions requiring immediate response.
#### Reasons:
- Approriate for request/response scenarios
- Provides easier contracts between consumers and services
- Easier for consumers to understand and integrate

### 4. Event-Driven communication for Asynchronous Processing
Use event processing for loosely coupled, asynchronous communication.
#### Reasons:
- Reduces direct dependencies
- Supports multiple consumers
- Improves scalibility 

### 5. Reusable Integration Services
Centralized technical integration logic within reusable integration services.

#### Reasons:
- Avoids duplication adapters and transformation logic
- Shields business applications from backend integration complexity
- Standardizes integration patterns
- Makes onboarding new systems easier

### 6. Stateless Integration Services
Keep Integration services predominantely stateless

#### Reasons:
- Enables horizontal scaling
- Simplifies deployment and recovery
- Avoids session affinity
- Improves resilience

### 7. Centralized Identity
Uses a centralized identity provider based on OAuth2/OIDC.
#### Reasons:
- Consistent authentication model
- Cenralized identity management
- Supports both user and service identities
- Avoid implementing authentication across services

### 8. Centralized Observability
Treat observability as cross-cutting platform concern.

#### Reasons:
- Enables end-to-end transaction tracing
- Provides centralized operational visibility
- Simplifies troubleshooting
- Enables proactive alerting

### Overall Decision Principle
- Use  APIs for sychronous interactions
- Workflow Orchestration for business process execution
- Events for asychronous processing and decoupling.
